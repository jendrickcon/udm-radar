# Post-Defense Feature Requirements — UDM-RADAR

**Document Version:** 1.0.0
**Accepted Baseline Git SHA:** `a79fb4838c5e2bc163cf943cda20afba9946d26b`
**Scope:** Functional, non-functional, and interface requirements responding to panel recommendations.

---

## 1. Functional Requirements (FR)

### FR-01: Continuous GWA Prediction & Uncertainty Range
- **Target Portals:** Student Portal (`student/dashboard.php`), Admin Portal (`admin/dashboard.php`, `admin/batch_predict.php`).
- **Requirement:**
  1. The platform must explicitly label predictive outputs as an **Estimated GWA** generated by a Decision Tree Regressor on the continuous point scale ($4.00\text{--}1.00$).
  2. The system must display an empirical prediction range $[\text{Lower Bound}, \text{Upper Bound}]$ derived from test MAE (e.g. $\text{Estimated GWA} \pm 0.15$), clamped strictly to $[1.00, 4.00]$.
  3. The platform must display a clear subline explaining that the forecast is an advisory estimate and not an exact guaranteed grade.
  4. Advisory risk triage (`LOW`, `MODERATE`, `HIGH`) must be visually presented as an institutional grouping rule applied to the estimated point grade, not as the model's direct output.

### FR-02: Student Academic Progression & Point Delta ($\Delta\text{GWA}$)
- **Target Portal:** Student Portal (`student/dashboard.php`, `student/grades.php`).
- **Requirement:**
  1. The student dashboard must display a primary comparative metric: **Point Change ($\Delta\text{GWA}$)** comparing Current/Projected GWA against the student's Previous Completed Term GWA.
  2. Visual directionality: A positive delta ($+0.25$) must be highlighted as an academic improvement; a negative delta ($-0.15$) must indicate a decline in point achievement.
  3. Secondary tooltip or contextual subline must present the relative percentage change ($+11.5\%$).
  4. A longitudinal line chart must plot the student's historical completed term GWAs alongside the current estimated GWA with distinct point glyphs.

### FR-03: Multi-Dimensional Administrator Analytics Filter Bar
- **Target Portal:** Admin Portal (`admin/analytics.php`, `admin/dashboard.php`).
- **Requirement:**
  1. Provide a synchronized, accessible filter bar supporting:
     - **School Year:** Dynamic selection from recorded terms (e.g. `2024-2025`, `2025-2026`, `2026-2027`).
     - **Semester:** `1st Semester`, `2nd Semester`, `Summer`.
     - **Curriculum Year Level:** `1st Year`, `2nd Year`, `3rd Year`, `4th Year`.
     - **Program Track:** `BSIT - Software Development`, `BSIT - Data Science`, `BSIT - Cyber Security`.
     - **Section:** Dropdown dynamically populated based on selected Year Level (e.g. `IT-31` through `IT-38`).
     - **Subject:** Dropdown filtered by selected year/term curriculum.
     - **Faculty Assignment:** Dropdown filtered by teaching assignments for the selected subject.
  2. Filter selections must update charts and tabular summaries asynchronously or via clean GET query parameters without full page reloads.

### FR-04: Comparative Year-Level & Semester-Level Aggregates
- **Target Portal:** Admin Portal (`admin/analytics.php`).
- **Requirement:**
  1. **Year-Level Comparison Chart:** Grouped bar chart comparing the **Average GWA by Year Level** across 1st Year, 2nd Year, 3rd Year, and 4th Year.
  2. **Semester Comparison Chart:** Longitudinal trend comparing the **Average GWA by Semester** across consecutive terms.
  3. Each comparative metric card must report:
     - Mean unit-weighted GWA
     - Total eligible student count ($N$)
     - Grade coverage rate (percentage of contributing grades complete)
     - Absolute point change from the prior comparable semester.
  4. Prohibit the term "Total GWA"; all aggregate metrics must represent valid mathematical means.

### FR-05: Same-Subject Cross-Section & Faculty Assignment Comparisons
- **Target Portal:** Admin Portal (`admin/analytics.php`).
- **Requirement:**
  1. Allow administrators to inspect class performance patterns for a specific subject across different sections and different assigned faculty members.
  2. Metrics displayed:
     - Class Average GWA for the subject-section
     - Difference from overall same-subject benchmark ($\Delta = \text{Class Avg} - \text{Subject Benchmark}$)
     - Student enrollment count
     - Grade completeness percentage
     - Support case referral count.
  3. **Mandatory Non-Evaluative Disclaimer:** Every view presenting faculty assignment comparisons must visibly display:
     > *Disclaimer: Academic comparisons across faculty assignments are intended for curriculum review and student support pacing. They do not measure teaching quality or faculty competence. Variances reflect class composition, prerequisite backgrounds, and section scheduling conditions.*

### FR-06: Intervention History & Faculty Interaction Dashboard Logs
- **Target Portals:** Admin Portal (`admin/dashboard.php`), Faculty Portal (`faculty/dashboard.php`).
- **Requirement:**
  1. Surface an **Intervention Overview** directly on the dashboard:
     - Total support cases generated by risk triage
     - Notices reviewed and issued by faculty
     - Notices deferred or pending action
     - Student receipt acknowledgments recorded
     - Closed support cases.
  2. Display responsiveness indicators:
     - Average latency from case creation to faculty notice issuance.
     - Average latency from notice issuance to student acknowledgment.
  3. Display a frequency breakdown of the six canonical reason codes.
  4. Provide drill-down links to view historical case timelines without leaving the administrative workflow.

### FR-07: Controlled Synthetic Longitudinal Dataset Generator
- **Target Environment:** `udm_radar_scratch` exclusively (STRICTLY PROHIBITED on `udm_radar`).
- **Requirement:**
  1. Provide a deterministic PHP CLI script (`tools/seed_longitudinal_analytics.php`) expanding synthetic cohorts across Years 1 to 4, 3 school years, and 2 semesters.
  2. Generate 10 controlled scenarios:
     - Stable section (minimal variance across terms)
     - Improving section (progressive GWA increase)
     - Declining section (gradual GWA decrease requiring review)
     - High-variance section (wide distribution of high and low performers)
     - Incomplete-record section (partial preliminary grades)
     - Same subject across multiple sections
     - Same subject across different faculty assignments
     - Active intervention cohort (notices issued and acknowledged)
     - Baseline non-intervention cohort
     - Multi-year progressing cohort (students tracked from 1st Year to 3rd Year).
  3. Zero genuine records; deterministic random seed; clean before/after row fingerprinting.

### FR-08: Visual Chart Refinement & Cognitive Simplification
- **Target Portals:** All portals.
- **Requirement:**
  1. Deprecate and remove confusing visual artifacts (e.g. multi-dimensional radar charts with conflicting axes, unscaled scatter plots).
  2. Standardize on high-clarity Chart.js visual types:
     - Clean longitudinal line charts with labeled data points.
     - Horizontal and grouped vertical bar charts with clear legends.
     - Standard distribution histograms with labeled bin boundaries.
  3. Every chart canvas must have an accessible textual summary and data table fallback.

## 2. Non-Functional Requirements (NFR)

| ID | Category | Requirement Specification |
|---|---|---|
| **NFR-01** | **Authorization & Scoping** | Strict role enforcement. Students inspect only their own longitudinal progression; Faculty inspect only their assigned class loads and referrals; Administrators inspect anonymized or authorized program-wide aggregates. |
| **NFR-02** | **Performance & Latency** | Multi-dimensional filter queries on synthetic cohorts must execute in under $200\text{ ms}$ on local MariaDB instances using indexed join keys (`idx_record_status`, `uq_grade_grain`). |
| **NFR-03** | **Accessibility (WCAG 2.1 AA)** | All chart colors must maintain at least a $4.5:1$ contrast ratio against light and dark portal backgrounds. Colors must not be the sole visual disambiguator (use dashed lines, hatched bars, or glyph markers). |
| **NFR-04** | **Mathematical Correctness** | Exclude non-numeric outcomes (`INC`, `DRP`, `P`) and legacy zeros from all unit-weighted averages and pass-rate denominators ($N = \text{Passed} + \text{Failed}$). |
| **NFR-05** | **Responsive Design** | Dashboard analytics cards, filter toolbars, and comparative charts must adapt cleanly from $360\text{ px}$ mobile screens to $1440\text{ px}$ desktop displays without horizontal overflow. |
| **NFR-06** | **Database Safety** | Automated synthetic data generators must enforce the `--target=scratch` flag and refuse execution if targeted against `udm_radar`. |
